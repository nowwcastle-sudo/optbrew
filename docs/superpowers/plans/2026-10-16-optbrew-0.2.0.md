# optbrew 0.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 한 번 부르면 설계된 감사 범위가 기본으로 돌고, 사용자 계정이 꼭 필요한 것만 처음에 묻는 optbrew 0.2.0을 만든다.

**Architecture:** 세 가지 블록으로 조립한다. ① **설정 블록** `references/*.json` + `core/config.mjs` — 조정하는 값의 유일한 자리. ② **검사 블록** `core/checks/<family>.mjs` — `prepare`가 한 번 계산한 공유값을 받아 관찰을 낸다. ③ **단계 블록** `core/stages.mjs` — `run(state, deps) → { state, halt? }` 모양. `scripts/run.mjs`가 순서대로 조립한다. 모든 증거는 **증거 저장 블록** `core/evidence-store.mjs` 하나로 쓰고 읽는다. 그래서 보고서 재현이 같은 경로로 모든 판정을 다시 계산한다.

**Tech Stack:** Node.js ≥ 22.4 내장 모듈만(`node:http`·`node:tls`·`node:net`·`node:child_process`·전역 `WebSocket`), Chrome DevTools Protocol, `node --test`, Python 3.10+ + `requirements-dev.txt`(기존 플러그인 검증 스크립트용).

**Spec:** `docs/superpowers/specs/2026-10-16-optbrew-beginner-audit-design.md` (D1~D26, C1~C22). 실행자는 계획과 함께 이 문서를 읽는다.

**Branch:** `fix/directory-sync-0.1.4` (PR #7). 0.1.4 커밋 위에 쌓고 한 번에 merge한다(D22).

## Global Constraints

- 런타임 의존성 0개. Node `engines`는 `>=22.4`(전역 `WebSocket` 안정 버전, C2).
- 뿌리와 `skills/` 안에 `.gitattributes` 없음(기존 `tests/line-endings.test.mjs`).
- 유료 호출은 사용자 본인 키로만. 저장소에 키 리터럴·기본 키 없음(D20).
- 키·프록시 자격 증명 값은 증거·보고서·로그·stdout·오류 메시지에 남기지 않는다. 키는 존재와 sha256 앞 8자만(C10).
- **버전 전환 시점:** Task 1의 `versions.json`은 현재 값으로 시작한다. 평가 `0.4.0`·프로토콜 `0.2.0`·계약 `2.0.0`은 Task 14에서, 릴리스 `0.2.0`은 Task 19에서 올린다. 그 사이 모든 Task는 `npm test` 전부 통과 상태로 끝난다.
- **재현 규칙:** 판정은 증거 저장 블록에 기록된 증거만으로 다시 계산할 수 있어야 한다. 네트워크 응답(렌더·CWV 포함)은 판정 전에 증거로 저장한다. 판정 임계값은 평가 원천 파일(`check-registry.json`)에 두어 `evaluation_hash`로 묶는다.
- **하드코딩 금지:** 코드에 URL·버전·조정 상한 리터럴을 두지 않는다. 설정 블록과 그 로더만 예외. Task 1부터 `tests/hygiene.test.mjs`가 강제한다.
- **가비지 금지:** 제품 코드에서 쓰이지 않는 export, 주석 처리된 코드, 진입점 밖 `console.log` 없음. 같은 테스트가 Task 1부터 강제한다. 쓰는 Task보다 먼저 설정 키나 함수를 만들지 않는다.
- 띄운 크롬·서버·프록시는 테스트와 실행이 끝날 때 프로세스 트리째 종료하고, 남은 것이 없는지 확인한다.
- 커밋 전 `npm test`와 `npm run -s scan-secrets`. 메시지 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- graft가 만든 `.ignore`·`graft/`와 `.sdlc-automate/`는 커밋하지 않는다.

## Review Focus

1. **봇 차단·챌린지 쪽** — headless 크롬에 403이나 챌린지 화면이 오면 `render-content`는 `unknown`(`render_blocked`)이다. 거짓 fail이면 안 된다. → Task 7 `render-content: a challenge page is unknown, not fail`.
2. **프록시 자격 증명** — `HTTPS_PROXY=http://user:pass@host:port`의 값이 어디에도 기록되지 않고, 인증 프록시에서도 수집·렌더가 된다. → Task 4 `proxy credentials never reach evidence or errors`, `authenticating proxy gets Proxy-Authorization`, Task 6 `renders through an authenticating proxy`.
3. **한글·공백 경로와 IDN 도메인** — `project (한글)` 경로, `Program Files` 크롬 경로, 한글 도메인(punycode)에서 렌더·키 파일·보고서가 깨지지 않는다. → Task 5 `launches chrome from a path with spaces and Hangul`, Task 6 `renders an IDN origin through its punycode host`.
4. **빈 키·깨진 키 파일** — 환경 변수가 빈 문자열이거나 `credentials.json`이 깨졌으면 「키 없음」으로 진행하고 내용을 출력하지 않는다. → Task 9 `empty env key and corrupt key file are treated as missing`.
5. **이미 켜진 사용자 크롬** — 사용자 크롬 창과 프로필을 쓰거나 닫지 않는다. → Task 5 `never reuses or closes a user's running chrome`.

### Task 4: 전송 블록 — 직접 / 프록시

**Files:** Create `skills/optbrew/scripts/core/transport.mjs`, `tests/transport.test.mjs`. Modify `core/collector.mjs` (`nodeTransport` 이동, `fetchScoped`에 `addressVetting` 옵션), `core/scope.mjs` L44.

**Interfaces:**
- `directTransport(req)` — 지금 `nodeTransport` 그대로.
- `proxyTransport(proxy: { host, port, authorization: string|null }): Transport` — `http.request({ host, port, method: 'CONNECT', path: \`${target}:${port}\`, headers: authorization ? { 'Proxy-Authorization': authorization } : {} })`의 `'connect'` 소켓 위에서 HTTPS는 `tls.connect({ socket, servername: hostname })`(SNI 기본 꺼짐, Node 22 문서). 응답 파싱은 직접 전송과 같은 함수.
- `parseProxy(env): { host, port, authorization } | null` — `env.HTTPS_PROXY ?? env.https_proxy`. userinfo는 `Basic base64(user:pass)`로만 바꾸고 원문을 버린다.
- `selectTransport({ env, resolve, probeHost }): Promise<{ transport, resolve, address_vetting: 'direct'|'proxy', proxy: { host, port } | null }>` — `resolve(probeHost)` 성공이면 직접. `ENOTFOUND`·`EAI_AGAIN`이고 프록시가 있으면 프록시. `NO_PROXY`(`no_proxy`)에 `probeHost`가 걸리면 프록시를 쓰지 않는다(존중). 프록시 모드의 `resolve`는 `[]`.
- `fetchScoped(input, { ..., addressVetting = 'direct' })`, `assertInScope(href, scope, addresses, { addressVetting = 'direct' } = {})` — `'proxy'`면 주소 검사만 건너뜀.

### Task 5: 크롬 블록 — 찾기·띄우기·범위 가로채기 세션

- `CdpClient = { send(method, params?, sessionId?): Promise<object>, on(event, fn): void }`.
