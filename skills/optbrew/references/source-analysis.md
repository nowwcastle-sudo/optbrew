# Source analysis tools

사이트의 소스 폴더가 있을 때, 고칠 곳을 찾기 전에 소스 분석 도구를 먼저 쓴다. 이 문서는 SKILL.md 2단계(도구 찾기)와 10단계(고치기 전 원인 찾기)가 쓴다.

## 도구 찾는 법

에이전트가 지금 쓸 수 있는 스킬, MCP, 플러그인 이름 목록에서 아래 이름을 찾는다. 하네스의 설정 파일은 열지 않는다. 설정 파일에는 사용자 비밀값이 있을 수 있고, 위치도 하네스마다 다르다. 이름이 맞는 도구가 하나도 없으면 "없음"이다.

| 이름 | 어디서 보이는가 | 쓰임 |
|---|---|---|
| `graft` | MCP 도구 `graft_find_code`, `graft_find_all`, `graft_trace_calls`, `graft_file_api`, `graft_repo_map`, 또는 스킬 `graft` | 기호가 정의된 파일·줄 찾기, 누가 부르는지 따라가기, 파일 하나의 전체 목록 보기 |
| `understand-anything` | 스킬 `understand`, `understand-chat`, `understand-diff` | 소스 폴더를 지식 그래프로 만들고 질문으로 구조를 묻기 |
| `graphify` | 스킬 또는 명령 이름 | 소스 폴더를 그래프로 만들어 위치와 연결을 묻는 도구로 알려진 이름. 이 저장소는 동작을 확인하지 않았다. 도구의 자체 안내를 먼저 읽는다 |
| `rea` | MCP 도구 `inspect_web_page`, `analyze_web_bundle`, `recover_javascript_sources`, `trace_web_source_location` | 소스 폴더가 없고 배포된 쪽·번들만 있을 때, 번들에서 원래 소스 위치를 되짚기 |

「어디서 보이는가」는 흔히 보이는 형태다. 형태는 조건이 아니다. 표의 이름과 같은 이름이 스킬, MCP, 플러그인 중 어느 형태로든 보이면 그 도구가 있는 것으로 센다(예: MCP 도구 없이 스킬 `graft`만 보여도 `graft`를 센다). 스킬 이름 앞에 플러그인 이름이 붙어 있으면(`personal:graft`) 콜론 뒤의 이름으로 맞춘다. 셀 때 그 도구를 실행해 보지 않는다. 10단계에서 써 보니 질의를 할 수 없으면 아래 「쓰는 법」 5번으로 간다.

목록에 없어도 "소스를 색인해 위치와 호출 관계를 묻게 해 주는 도구"라면 같은 방식으로 쓸 수 있다. 이름을 `source_tools`에 그대로 적는다.

## 쓰는 법

1. 고칠 문제마다 질의를 한 문장으로 정한다. 예: "`<head>` 밖에서 `<meta name=description>`을 만드는 템플릿은 어디인가", "제목을 만드는 코드는 어디인가".
2. 도구로 질의를 보낸다. 읽기 질의만 한다. 도구가 소스를 바꾸거나 소스를 밖으로 보내는 기능은 쓰지 않는다.
3. 도구가 가리킨 파일과 줄을 직접 열어 맞는지 확인한다. 도구의 답을 확인 없이 믿지 않는다.
4. 도구가 설치돼 있지 않으면 설치하지 않는다. 설치는 환경을 바꾸는 일이므로 사용자의 몫이다. 없는 채로 5번으로 간다.
5. 맞는 도구가 없으면 직접 분석한다(파일 검색, 열어 읽기). 그리고 사용자에게 한 줄 알린다: "소스 분석 도구가 없어 직접 읽어 찾았습니다. 놓친 곳이 있을 수 있습니다."

## 기록

`change finish`가 고친 파일의 `ChangeRecord.analysis`에 이렇게 쓴다. `--tool`(여러 번 쓸 수 있다)이 `tools`, `--query`(여러 번 쓸 수 있다)가 `queries`, `--self-analysis`가 `self_analysis`다. `--tool` 없이 끝내면 `self_analysis`는 `true`이고, `--tool`을 쓰면 `false`다.

```json
{
  "tools": ["graft"],
  "queries": ["<head> 밖에서 meta description을 만드는 템플릿은 어디인가"],
  "self_analysis": false
}
```

- `tools`: 실제로 쓴 도구 이름. 쓰지 않았으면 빈 배열이다.
- `queries`: 도구에 보낸 질의 문장. 도구 없이 분석했으면 빈 배열이다.
- `self_analysis`: 도구 없이 직접 읽어서 원인을 찾았으면 `true`다. 도구로 위치를 찾고 직접 확인만 했으면 `false`다.
