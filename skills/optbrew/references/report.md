# Report packet and evidence contract (v0.1.0)

`node skills/optbrew/scripts/cli.mjs report --input <packet.json> --output-dir <new-directory>` writes `report.json` and `report.md`. It makes no network or paid calls. It refuses to replace an existing report. A report is a local audit artifact; a local passing verification does not establish deployment, indexing, traffic, ranking, citations, or business impact.

`ReportPacket` retains the approved `run_context`, raw `baseline.input`, optional `after.input`, their `score()` results, `compare()` result, metrics, findings, changes, costs, remaining work, and source identity. `evidence_root` points to the run directory. The CLI resolves a relative root against the packet's directory. Each `evidence_index` item has `{ref,sha256,kind,run_id,source_ref?}`. Every indexed file is reopened, checked against its SHA-256, and contained by the resolved run directory. The context file at `run_context.evidence_ref` must contain exactly that run context. Family and URL applicability decisions and observations must resolve to indexed evidence. Collector observations additionally require `audit_ref`, the Task 5 evidence index, its observation and collection files, and matching raw file hashes.

Owner export metrics are replayed with `normalizeImport()` from evidence JSON `{kind:"native_export",run_id,provider,rows,metadata}`. AI panel metrics are replayed with `measurePanel()` from `{kind:"panel",run_id,panel,responses,evaluations}`. The panel hash and question, engine, surface, model, search, locale and region conditions must match the run protocol. The persisted `CostLedger` snapshot is indexed at `costs.evidence_ref`; unknown settlement, observed overrun and `host_policy` limitations stay visible. Do not include secrets, account tokens, personal records, or private card text in a packet or evidence directory.

Findings merge only when check, unit and normalized problem text agree. Every contributing source remains on the merged finding. A finding must match a failed or unknown check observation. The curated remediation catalog chooses only an applicable, directly relevant mechanism; official sources lead the evidence order. A remote finding has a proposed change location and validation method but remains `proposed_only`. A `ChangeRecord` may advance to `verified_local` or `verified_production` only when its indexed verification receipt matches run ID, change ID and status; production also needs an explicit deployed receipt. No SEO gain is predicted. Hypothetical readiness changes belong in a separately marked scenario, never in `after`.

Both formats show four tables: score, remediation, actual outcomes, and remaining work. Score arithmetic comes from `score()` and `compare()`. Actual outcome pairs require the same native metric definition, filters, sample selection and panel, plus two adjacent complete 28-day windows. An absent or ambiguous value stays unknown. Markdown escapes pipes, HTML and line breaks in evidence and titles. `data_class:synthetic` labels fixture reports and cannot be presented as observed production performance.
